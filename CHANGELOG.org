#+TITLE: Changelog

* 0.7.9
Every sheet and dialog now behaves the same way. An x on the title line leaves the whole chain of screens at once; only what is above the buttons scrolls, so nothing slides under Cancel; buttons in a row are the same size; and settings with a default have a Reset button. Settings confirmations show on the Emacs screen. The command for refiling a copy is org-refile-copy. Verified: the seven browser checks and the unit tests.

* 0.7.8
Typing a name in Save as no longer hides the keyboard on every character. Archive follows Emacs more closely: it records the TODO word and inherited tags, keeps the entry's own category and existing properties, realigns tags when the level changes, and archive-to-sibling reuses an Archive heading and works on top-level headings. Archiving from an unsaved tab says it needs a file. Capture creates a target file that does not exist yet, and %a above the first heading links to that line. Verified: Emacs 30.1 results for archive and capture.

* 0.7.7
Capture and refile work as in Emacs. C-c c files a note from a template set as init.el writes it (Settings, Emacs, Capture templates), with Emacs's % escapes and placement rules. C-c C-w moves a heading and its subtree to a chosen target, C-c M-w copies it, and C-c C-x C-a archives it, keeping where it came from in properties; targets and the archive location are set in Settings, Emacs. Verified: results from Emacs 30.1 for capture, refile and archive.

* 0.7.6
Settings gathers the Emacs ones (agenda files, beep, Emacs keys, hide leading stars, tag column) under one Emacs entry. In the Outline view a heading's actions are grouped as Text, Structure, Dates and clock, and State, and Edit body changes the text under it. Date prompts read what Emacs reads: weekdays, month names, 12/5, 3.1.2027, +fri and a bare day number. The agenda draws Emacs's time grid with a now line, and categories follow #+CATEGORY and :CATEGORY:. Repeater units cycle d, w, m, y; effort accepts a bare number. Verified: replayed Emacs 30.1 results for date prompts, the time grid, categories, clocking and effort.

* 0.7.5
Clocking works as in Emacs: C-c C-x C-i starts a clock in a :LOGBOOK: drawer, C-c C-x C-o stops it and records the time, C-c C-x C-q cancels it. C-c C-x e sets an effort. The agenda reads your agenda files, kept as ~org-agenda-files~ the way init.el sets it; C-c [ and C-c ] edit the list, and Settings shows it. Open starts in the folder you last used, the agenda has a Today button and the . key, and View lists Agenda, Outline, Text. Verified: replayed Emacs 30.1 results for clocking, effort, repeaters and timestamp keys.

* 0.7.4
A Back button, at the bottom left of the text, returns to where you came from (a tab, an agenda row, Go to line, a search, M-< and M->); hold it to see where it goes. The agenda has bolder arrows and moves with a swipe or f and b. Finishing a repeating task now also moves a plain repeating timestamp in the body, and S-left and S-right on a timestamp move the day, all as Emacs does; the stamps use your local time. WebDAV lists one folder at a time and no longer reuses an old copy of a file. Verified: replayed 25 Emacs 30.1 results for repeaters and timestamp keys.

* 0.7.3
WebDAV now reads from the server on every request instead of letting the browser reuse an old copy, which could show the original file after a save and then refuse the next save with 412; listing folders is also faster. A refused save now reports both ETags. Sparse trees highlight the matching text or TODO keyword, and S-up and S-down on the key row change a timestamp or heading, as the keyboard does. Verified: browser checks for the key row and highlights, unit tests for WebDAV and sparse trees.

* 0.7.2
After a sparse tree, TAB on a heading that holds none of the tree open now unfolds it as usual; before, it folded a match under another heading. TAB on a heading with part of the tree open still folds it and drops the tree, as in Emacs. Verified: a unit test for both cases.

* 0.7.1
Query replace's answer buttons now sit on a row below the prompt, so the prompt is no longer hidden behind them. A sparse tree keeps the cursor on its text (or on the heading above it when its line folds away), so TAB acts on the heading you expect. The key event log is now a screen of its own, opened from Settings, that records key events and lets you Copy or Clear them, instead of covering the top of the editor. Verified: browser checks for each.

* 0.7.0
The agenda: View, then Agenda (or C-c a a) shows the open files by Day, Week or Month with ‹ and › to move, and Views switches to the TODO list (C-c a t), a tags view (C-c a m) or a search (C-c a s); tapping a row goes to its heading. Scheduled and deadline entries, repeats, overdue tasks, and deadline warnings follow Emacs. The date prompt now also reads month names (dec 3, 3 dec 2026), am and pm, and a time range (10:00-11:30). Verified: replayed 15 Emacs 30.1 agenda and 6 typed-date results.

* 0.6.0
Dates: C-c C-s schedules and C-c C-d sets a deadline (typed as 2026-12-01, +3d, tomorrow, with an optional time), C-c . and C-c ! insert an active or inactive timestamp, and S-up and S-down on a timestamp change the year, month, day, hour or minute under the cursor (on the closing bracket they make it inactive or active). Finishing a repeating task (+1w, ++1w, .+1w) moves its date on, reopens it, and records :LAST_REPEAT: and a State line. Verified: replayed Emacs 30.1 results for 21 date cases.

* 0.5.1
Sparse trees by match: C-c / m asks for a match and shows the headings that fit, with the headings above them. A match can use tags (work, work+urgent, work-urgent, home|urgent; tags are inherited from the headings above), TODO keywords after a slash (work/TODO), LEVEL=2, and a property value such as Effort="5h". Verified: replayed Emacs 30.1 results for eight matches.

* 0.5.0
The Text view gained regexp search (C-M-s, C-M-r, or M-r inside a search, using Emacs regexp syntax), query replace (M-% and C-M-% with Emacs's keys y, SPC, n, DEL, !, ., q, RET and ^, each with a button on a touch screen), and sparse trees (C-c / r for a regexp, t for unfinished TODO entries, T for a keyword; C-c C-c clears the highlights). The first C-g in a failing search now removes the failing text, as Emacs does. Verified: replayed Emacs 30.1 results for regexps, query replace and sparse trees.

* 0.4.7
Search now follows Emacs: past the last match it fails first and a further C-s wraps, changing direction keeps the current match, and C-s on an empty field recalls the last search. Prompts and echo messages use Emacs's words (Priority A-C, SPC to remove:, Foo value:, Priority of current item set to B, TODO state changed to TODO), and M-left on plain text moves a word back. Verified: replayed Emacs 30.1 results for search, prompts, movement and priorities.

* 0.4.6
The key row's arrows now move as C-p, C-n, C-b and C-f do: by screen line on wrapped text, keeping the column, and with the beep at the ends; with Shift they still extend the selection. The README and SPEC now describe the search keys, key row, scrolling and key event log. Verified: the key row's arrows match the C-n goal-column behavior.

* 0.4.5
The Text view now scrolls to the cursor after a movement key, a jump or a search, and puts the cursor in the middle of the screen when it was off screen, as Emacs does; before, the cursor moved but the text stayed where it was. Verified: M-< and M-> show the start and end of a long buffer and a search scrolls to its match.

* 0.4.4
Settings has a Key event log: when on, the top of the screen lists what the keyboard sends the editor (key, code, typed text, composition, the keys held on the key row) and the chord Serita made of it, so a key that does nothing can be diagnosed from a screenshot. Verified: the log shows the chord for a pressed key.

* 0.4.3
Ctrl and Meta on the key row now work with an on-screen keyboard: the key row's held keys were being dropped when the keyboard announced a letter, so the letter was inserted instead of run. C-n, C-p, C-a, C-e, M-<, M->, C-s and C-c sequences now run from the key row. The Line button asks in the minibuffer in the Text view. Verified: the key-row cases reproduce the failure without the fix and pass with it.

* 0.4.2
C-s and C-r start a forward or backward search in the Text view, and press again inside the search for the next or previous match. Letters typed on an on-screen keyboard now count as key presses when Ctrl or Meta is held on the key row, or after a prefix such as C-c, so C-n, C-p, C-s and C-c C-t work from the key row instead of inserting the letter. Cancelling a search returns the cursor to where it began. Verified: the related browser checks pass.

* 0.4.1
Same as 0.4.0, repackaged with the files at the top level of the zip.

* 0.4.0
Priorities, properties and the minibuffer. S-up and S-down change a heading's priority, S-left and S-right walk its TODO states, and C-c C-t works from anywhere in the heading's body; a parent's ~[n/m]~ cookie follows its children's states. Property drawers start folded, TAB folds them, and C-c C-x p sets a property. In the Text view, Find, Go to line, tags, priority and property questions are asked in the minibuffer at the bottom, with M-x and completions; the Outline view keeps touch dialogs and gets a Commands list in the menu. Verified: priorities, TODO states and properties match Emacs 29.3 results.

* 0.3.0
The Text view now has the Emacs movement keys: C-n and C-p by screen line with a remembered column, C-f, C-b, C-a, C-e, M-f, M-b, M-<, M->, C-v and M-v, and M-right moves a word on plain text. Errors and C-g give the short beep Emacs gives, with a setting to turn it off. C-RET works from a heading's body, and Installed version and New version are aligned in two columns. Verified: movement matches Emacs 30.1 results.

* 0.2.2
In Settings, Installed version and New version now show the label on the left and the version on the right, with space between them.

* 0.2.1
C-RET on a line of a heading's body now starts a new heading after that heading's subtree, as Emacs does; before, it did nothing there. Found by replaying the Emacs conformance cases against the Text view. Verified: the cases for TAB, S-TAB, M-RET, M-arrows, checkboxes, tags, TODO cycling and startup folds match Emacs.

* 0.2.0
Serita reopens your files, tabs, folds and view where you left them, with unsaved edits and scratch text kept as drafts. Appearance in Settings sets Light, Dark or System, the font (monospace by default, like Emacs), the text size (12 to 32, default 18) and the paragraph spacing in the Outline view. The tag column is a setting (-77 by default, as in Emacs). Swiping a heading right to left works like TAB. Buttons are smaller, each view can show or hide its tool row, and commits now refuse to run when git has no name or email.

* 0.1.9
The on-screen keyboard no longer appears on its own: the tool row buttons, Select all, Go to line and accepting a search leave it as it was. Only tapping the text or the keyboard button raises it.

* 0.1.8
The top bar, tabs, tool row and Emacs key row now stay on screen when the on-screen keyboard opens or the text scrolls. The page fits the space above the keyboard instead of scrolling behind it.

* 0.1.7
A tool row sits under the tabs: undo and redo, line numbers, wrap, text size, and a Lines and text menu (go to line, select all, copy all, duplicate, delete into a kill ring, move, indent). M-RET starts a heading at the cursor, and pressing TAB again continues the heading's cycle where the last press left it, as Emacs does, so a heading whose children have no text now takes three presses. Sign-off on every commit is added automatically.

* 0.1.6
Editing a heading's title and inserting a heading now use a small popup, so the Outline view no longer switches to the Text view. Checkboxes toggle in both views (tap, or C-c C-c), and the parent checkbox and the [2/4] and [50%] counts follow. List items fold, move and change indentation with TAB and the M-arrows. C-c is typed with Ctrl on the key row, so a keyboard's own C-c still copies. Find opens the folds that hide a match and closes them again if you cancel.

* 0.1.5
Org files now have two views over one document: an Outline view of foldable headings with tap actions (change TODO state, promote, demote, move, add a heading, set tags, toggle checkboxes), and the Text view, which folds the same headings and shows "..." after them. Folding follows the file's #+STARTUP line. A new Emacs keys setting adds TAB, S-TAB, M-arrows, C-RET and C-c C-t, with a scrolling key row and a floating, draggable version, for phones without those keys. The current tab is highlighted more clearly.

* 0.1.4
A new version no longer replaces the running one on its own. The message line says a version is ready, Menu and Settings show the installed and the new version, and Restart to update switches over when you choose, so an update never arrives in the middle of editing. The app also looks for updates when you return to it or come back online.

* 0.1.3
Files on your device can now be opened and saved: under Change, Device files opens the device's own file picker, and Save writes back to the same file. The app's own storage is now called App storage, so the name says what it is; before, "local" could be mistaken for the files on your Chromebook. Reconnecting after a restart asks your permission again before writing.

* 0.1.2
Saves you made offline are now sent when you reconnect, and the mode line shows how many are waiting. If the server copy changed in the meantime, a list names the files and you settle each one with Merge, Keep mine or Use theirs, so an offline session can no longer end in a lost edit. A file open in a tab reloads with the settled text.

* 0.1.1
The screens now follow your own app: white rounded-rectangle buttons, flat tabs with a blue underline, and bottom sheets with a handle and ruled rows. The File sheet lists up to 20 recently opened or saved files, five visible at a time, with a mark for those already open; press and hold one to drop it from the list, or use Clear recents.

* 0.1.0
The first version you can install and try. It opens, edits and saves plain text in tabs, from this device, GitHub or WebDAV, with a file browser that shows sizes, manual Save, Save as and Save some buffers, and a prompt when the server copy changed. Find searches as you type, and Settings sets up your storage and exports it to, or imports it from, an Org file with optional encryption. It starts offline after the first visit.

* 0.0.7
Settings can now be written to an Org file and read back on another device, so a second install starts configured the same way. Tokens and passwords go in too; with a passphrase they are encrypted, and without one the file says so and should be kept private. A wrong passphrase stops the import and changes nothing. The Settings panel buttons arrive with the app shell.

* 0.0.6
File lists now carry each file's size, so Open can show how big a file is before you pick it. GitHub and the app's own storage always know the size; a WebDAV server that leaves it out shows a blank instead of a guess. Unsent edits and files created offline show their own size.

* 0.0.5
Files on a WebDAV server can now be read, saved, listed and deleted, so your own server works as well as GitHub. Saves are checked against the version you last saw and refused when the server copy has changed, and missing folders are created for you. Offline saving and conflict handling work the same way as for GitHub.

* 0.0.4
Saves made while offline are now kept and sent when you are back online, so you can keep working on a train and nothing is lost. If someone changed the same file on the server in the meantime, you get both versions and the original to merge or choose from, and a delete you made offline is treated the same way. Files you have already opened stay readable offline.

* 0.0.3
Files in a GitHub repository can now be read, saved, listed and deleted, with one commit per save and your token kept out of the code. A save that would overwrite newer text on the server is caught and reported as a conflict, and a new three-way merge can combine changes made in different places while leaving true clashes for you to settle. This is the storage half of the sync you described; the offline cache and the prompt come next.

* 0.0.2
Files can now be saved in the app's own storage with a version on every save, so a stale save is caught instead of overwriting newer text. The browser side of the app interface routes names like ~github:home.org~ to the right place and says plainly when a provider is not set up or the browser lacks a feature, instead of pretending. This is the storage groundwork the first installable release builds on.

* 0.0.1
The repository starter: an Org parser that returns your text exactly as it was, a document model whose undo restores it exactly, the storage naming used by the init files (~github:home.org~), and the interface each platform will implement. It exists so the project can live on GitHub with its license, clean-room checks and test runs from the first commit.
