#+TITLE: Changelog

* 0.2.2
In Settings, Installed version and New version now show the label on the left and the version on the right, with space between them.

* 0.2.1
C-RET on a line of a heading's body now starts a new heading after that heading's subtree, as Emacs does; before, it did nothing there. Found by replaying the Emacs conformance cases against the Text view. Verified: the cases for TAB, S-TAB, M-RET, M-arrows, checkboxes, tags, TODO cycling and startup folds match Emacs.

* 0.2.0
Serita reopens your files, tabs, folds and view where you left them, with unsaved edits and scratch text kept as drafts. Appearance in Settings sets Light, Dark or System, the font (monospace by default, like Emacs), the text size (12 to 32, default 18) and the paragraph spacing in the Outline view. The tag column is a setting (-77 by default, as in Emacs). Swiping a heading right to left works like TAB. Buttons are smaller, each view can show or hide its tool row, and commits now refuse to run when git has no name or email.

* 0.1.9
The on-screen keyboard no longer appears on its own: the tool row buttons, Select all, Go to line and accepting a search leave it as it was. Only tapping the text or the keyboard button raises it.

* 0.1.8
The top bar, tabs, tool row and Emacs key row now stay on screen when the on-screen keyboard opens or the text scrolls. The page fits the space above the keyboard instead of scrolling behind it.

* 0.1.7
A tool row sits under the tabs: undo and redo, line numbers, wrap, text size, and a Lines and text menu (go to line, select all, copy all, duplicate, delete into a kill ring, move, indent). M-RET starts a heading at the cursor, and pressing TAB again continues the heading's cycle where the last press left it, as Emacs does, so a heading whose children have no text now takes three presses. Sign-off on every commit is added automatically.

* 0.1.6
Editing a heading's title and inserting a heading now use a small popup, so the Outline view no longer switches to the Text view. Checkboxes toggle in both views (tap, or C-c C-c), and the parent checkbox and the [2/4] and [50%] counts follow. List items fold, move and change indentation with TAB and the M-arrows. C-c is typed with Ctrl on the key row, so a keyboard's own C-c still copies. Find opens the folds that hide a match and closes them again if you cancel.

* 0.1.5
Org files now have two views over one document: an Outline view of foldable headings with tap actions (change TODO state, promote, demote, move, add a heading, set tags, toggle checkboxes), and the Text view, which folds the same headings and shows "..." after them. Folding follows the file's #+STARTUP line. A new Emacs keys setting adds TAB, S-TAB, M-arrows, C-RET and C-c C-t, with a scrolling key row and a floating, draggable version, for phones without those keys. The current tab is highlighted more clearly.

* 0.1.4
A new version no longer replaces the running one on its own. The message line says a version is ready, Menu and Settings show the installed and the new version, and Restart to update switches over when you choose, so an update never arrives in the middle of editing. The app also looks for updates when you return to it or come back online.

* 0.1.3
Files on your device can now be opened and saved: under Change, Device files opens the device's own file picker, and Save writes back to the same file. The app's own storage is now called App storage, so the name says what it is; before, "local" could be mistaken for the files on your Chromebook. Reconnecting after a restart asks your permission again before writing.

* 0.1.2
Saves you made offline are now sent when you reconnect, and the mode line shows how many are waiting. If the server copy changed in the meantime, a list names the files and you settle each one with Merge, Keep mine or Use theirs, so an offline session can no longer end in a lost edit. A file open in a tab reloads with the settled text.

* 0.1.1
The screens now follow your own app: white rounded-rectangle buttons, flat tabs with a blue underline, and bottom sheets with a handle and ruled rows. The File sheet lists up to 20 recently opened or saved files, five visible at a time, with a mark for those already open; press and hold one to drop it from the list, or use Clear recents.

* 0.1.0
The first version you can install and try. It opens, edits and saves plain text in tabs, from this device, GitHub or WebDAV, with a file browser that shows sizes, manual Save, Save as and Save some buffers, and a prompt when the server copy changed. Find searches as you type, and Settings sets up your storage and exports it to, or imports it from, an Org file with optional encryption. It starts offline after the first visit.

* 0.0.7
Settings can now be written to an Org file and read back on another device, so a second install starts configured the same way. Tokens and passwords go in too; with a passphrase they are encrypted, and without one the file says so and should be kept private. A wrong passphrase stops the import and changes nothing. The Settings panel buttons arrive with the app shell.

* 0.0.6
File lists now carry each file's size, so Open can show how big a file is before you pick it. GitHub and the app's own storage always know the size; a WebDAV server that leaves it out shows a blank instead of a guess. Unsent edits and files created offline show their own size.

* 0.0.5
Files on a WebDAV server can now be read, saved, listed and deleted, so your own server works as well as GitHub. Saves are checked against the version you last saw and refused when the server copy has changed, and missing folders are created for you. Offline saving and conflict handling work the same way as for GitHub.

* 0.0.4
Saves made while offline are now kept and sent when you are back online, so you can keep working on a train and nothing is lost. If someone changed the same file on the server in the meantime, you get both versions and the original to merge or choose from, and a delete you made offline is treated the same way. Files you have already opened stay readable offline.

* 0.0.3
Files in a GitHub repository can now be read, saved, listed and deleted, with one commit per save and your token kept out of the code. A save that would overwrite newer text on the server is caught and reported as a conflict, and a new three-way merge can combine changes made in different places while leaving true clashes for you to settle. This is the storage half of the sync you described; the offline cache and the prompt come next.

* 0.0.2
Files can now be saved in the app's own storage with a version on every save, so a stale save is caught instead of overwriting newer text. The browser side of the app interface routes names like ~github:home.org~ to the right place and says plainly when a provider is not set up or the browser lacks a feature, instead of pretending. This is the storage groundwork the first installable release builds on.

* 0.0.1
The repository starter: an Org parser that returns your text exactly as it was, a document model whose undo restores it exactly, the storage naming used by the init files (~github:home.org~), and the interface each platform will implement. It exists so the project can live on GitHub with its license, clean-room checks and test runs from the first commit.
