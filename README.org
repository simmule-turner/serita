#+TITLE: Serita
#+SUBTITLE: Reads and writes Org files

Serita is an Org-mode app for phones, tablets, Chromebooks and desktop browsers. It is MIT licensed and written from scratch.

* Use
Open the app in a browser and install it from the browser's menu; it then starts offline.

The toolbar has Files and Save at the left, Find in the middle, and View and Menu at the right. Each file is a tab; the × closes it. Saving is manual.

** Files
- New :: opens a ~*scratch*~ buffer.
- Open :: picks a file from app storage, GitHub or WebDAV, with its size. Under Change, Device files opens your device's own file picker.
- Save :: writes the current tab to its file.
- Save as :: writes it to another storage or name; with Device files, your device's save dialog opens.
- Save some buffers :: asks about each unsaved tab: Yes, No, Save all or Cancel.

** Views
View switches between Outline and Text; both show the same document and the same folding.

The Outline view lists headings as a tree. The arrow at the left of a heading cycles its visibility, like TAB in Emacs: folded, children, whole subtree. Tap a TODO word to change its state, a checkbox to toggle it, and a heading's title for its actions. The values that are set show as chips (state, priority, scheduled, deadline, tags, effort) that you tap to change; + Add lists what is not set, plus Property, Clock in and Timestamp. Below are Text (edit the title or the body) and Structure (promote, demote, the subtree, move, insert a heading below, refile, archive). Edit title and Insert heading below open a popup with a text field, where Enter accepts it; Edit body opens a larger field for the text under the heading.

A checkbox toggles when you tap it. The checkbox of the item above it, and the ~[2/4]~ or ~[50%]~ counts of that item and of the heading, follow. A list item folds with its arrow, like a heading.

The Text view shows the raw Org text, with ~...~ after a folded heading. A file's ~#+STARTUP:~ line sets what is folded when it opens; without one, everything is shown.

** Emacs keys
Settings, Emacs, Emacs keys, turns on these keys in the Text view:
- TAB :: cycles the heading or list item at the cursor; S-TAB cycles the whole buffer: overview, contents, show all.
- M-up, M-down :: move the subtree, or the list item with its sub-items, up or down.
- M-left, M-right :: promote or demote the heading; on a list item, change its indentation and leave its sub-items; with Shift, the whole subtree or the sub-items too.
- C-RET :: inserts a heading after the current subtree, from the heading or anywhere in its body.
- C-n, C-p :: move down or up one screen line, keeping the column; C-f, C-b move a character; C-a, C-e go to the start or end of the line; M-f, M-b move a word; M-<, M-> go to the start or end of the text; C-v, M-v move a screen down or up. On plain text M-right moves a word.
- The text scrolls to keep the cursor in view after any movement or search, and puts the cursor in the middle of the screen when it was off screen.
- C-g :: quits a pending key or command. Errors and quits give a short beep (Settings, Emacs, Beep on errors).
- C-s, C-r :: search forward or backward; again inside the search, the next or previous match; on an empty field, the last search. C-g or the cancel button returns to where you started.
- C-c C-t :: changes the TODO state, from the heading or anywhere in its body. S-right and S-left go to the next or previous state; the parent's ~[2/4]~ count follows.
- S-up, S-down :: raise or lower the priority of the heading. C-c , asks for it: A, B, C, or SPC to remove.
- C-c C-x p :: sets a property: asks for the name, then the value. The drawer is created when needed and starts folded. M-x org-delete-property removes one.
- C-c C-q :: sets the tags.
- M-x :: runs a command by name. Type any words of the label or name; TAB completes, RET runs.
- C-c C-c :: toggles the checkbox on the line; on a ~[/]~ or ~[%]~ cookie it recounts it.
- M-RET :: starts a heading at the cursor: above a heading when the cursor is at its start, below it at its end, and in other text the line breaks there and the rest becomes the heading.
- C-/, C-_, C-x u :: undo; C-? redoes.
- C-k :: kills to the end of the line, then the line break; consecutive kills join. C-S-DEL kills the whole line, and C-y yanks the latest kill.
- M-g g :: goes to a line. C-x h selects everything.

To type C-c or C-x, use Ctrl on the key row and then the letter; a keyboard's own C-c and C-x still copy and cut.

Above the mode line, a row of keys stands in for a keyboard: Meta, Ctrl and Shift apply to the next key, and a letter typed on the on-screen keyboard after Ctrl or Meta is the key chord, for example Ctrl then n is C-n. Tab and the arrows follow; the arrows move as C-p, C-n, C-b and C-f do, and with Shift they extend the selection. The keyboard button shows or hides the on-screen keyboard. Float turns the row into a panel you can drag; Dock puts it back. Pressing a key never opens the keyboard.

Settings, Key event log, records what the keyboard sends and which key chord Serita made of it. Turn it on, press the keys in the editor, then open it again to read the log, Copy it or Clear it; it helps when a key does not do what it should.

Settings, Emacs, Hide leading stars, shows only the last star of each heading. Indent files on open turns on org-indent-mode: each level is indented two columns and the text under a heading lines up with the heading's text, with nothing added to the file. A file can ask for it with ~#+STARTUP: indent~ or refuse with ~#+STARTUP: noindent~, and the palette command Indent mode toggles it for the file you are in.

** Tool row
Under the tabs, one row of buttons: undo, redo, line numbers, wrap, smaller text, larger text, and Line. Settings turns the row on or off for each view. In the Outline view the row keeps undo, redo and the two size buttons. Line opens Lines and text: go to a line, select all, copy all, duplicate, delete (to the kill ring), move, indent and outdent the line. Typing within a second is one undo step; each structure edit is its own.

** Appearance
Menu, Settings, Appearance: Theme (System, Light or Dark), Font (monospace by default, or another, or a font name from your device), Font size (12 to 32; A− and A+ change the same size) and Paragraph spacing (0 to 32 px, Outline view). Menus and buttons keep a fixed size.

** Tag column
Menu, Settings, Emacs, Tag column. A negative number ends the heading line at that column (-77 by default); a positive number starts the tags there; 0 puts them one space after the title.

** Restore
Open files, the current tab, folds, the view and unsaved edits come back when you reopen Serita. Settings, Restore open files on start turns it off.

** Back
The arrow at the bottom left of the text goes back to where you came from: a place you left by tapping a tab, a row of the agenda, Go to line, a search, or M-< and M->. After an agenda row it returns to the agenda. Hold it to see where it would go. C-x C-SPC does the same.

** Swipe
Swipe a heading in the Outline view from right to left to fold or unfold it, like TAB.

** Minibuffer
In the Text view, questions are asked on the line at the bottom, as in Emacs: the prompt sits in the field, RET accepts and C-g or Esc cancels. The buttons ✓ and ✕ do the same by touch. Completions appear above the key row.

In the Outline view, the same questions are touch dialogs. Menu, then Commands, lists the commands that work without a cursor, with their Emacs names and keys; type to narrow the list, or tap Show all for every command in alphabetical order.

** Find
Type to search. The prompt shows ~I-search:~, ~Wrapped I-search:~ or ~Failing I-search:~. The match is highlighted; ▲ and ▼ go to the previous and next match. Past the last match the search fails; one more press wraps. C-s on an empty field recalls the last search. A lowercase query ignores case; an uppercase letter makes it exact. Return keeps the cursor on the match, and × returns to where you started.

** Regexp search
C-M-s and C-M-r search forward and backward for an Emacs regexp; M-r inside a search switches between plain and regexp. The prompt reads ~Regexp I-search:~.

** Replace
M-% replaces text; C-M-% replaces a regexp (\& is the match, \1 a group, \# the count). Answer each match with y or SPC (replace), n or DEL (skip), ! (replace the rest), . (replace and stop), q or RET (stop), ^ (back). A replacement follows the case of the match unless the search has a capital. On a touch screen each key has a button. Example: M-% ~cat~ RET ~dog~ RET, then ~!~.

** Sparse trees
C-c / r shows the lines that match a regexp and the headings above them; C-c / t shows unfinished TODO entries; C-c / T asks for a keyword; C-c / m asks for a match such as ~work+urgent~, ~work/TODO~, ~LEVEL=2~ or ~Effort="5h"~ (tags are inherited). C-c C-c removes the highlights; TAB folds the heading. In the Outline view, Menu, then Commands has the same entries.

** Tables
In the Text view, with the cursor in a table: TAB aligns the table and moves to the next field (a new row at the end), S-TAB to the previous; RET moves to the next row; S-RET copies the field above (numbers and dates count up); M-RET splits the field at the cursor. M-up and M-down move the row; M-left and M-right move the column; M-S-up deletes the row and M-S-down inserts one; M-S-left deletes the column and M-S-right inserts one. C-c - adds a horizontal line, C-c RET adds one and moves below it, C-c C-c aligns, C-c ? shows the field's coordinates.
C-c ^ sorts the rows between horizontal lines by the column: a, n or t for alphabetic, numeric or time order, a capital letter for the reverse. C-c | asks for a size such as ~3x4~ and makes a table; with text selected it turns the lines into rows. Palette: ~org-table-transpose-table-at-point~, ~org-table-sort-lines~, ~org-table-align~.
In the Outline view a table is a grid. Tap a cell for its sheet: edit the cell, change its row or column, or sort by it. A width cookie such as ~<10>~ shortens what the grid shows, not the text. In Settings, Emacs: Wrap table cells (~org-table-widget-wrap-columns~) wraps long cells so rows grow taller, Table width (~org-table-widget-max-width-fraction~) sets how much of the screen a table may use, and Stripe table rows (~org-table-widget-zebra-stripe~) shades every other row. With wrapping on, a width cookie sets that column's width and its text wraps inside it.

** Dates
C-c C-s schedules the heading and C-c C-d sets its deadline; C-c . inserts a timestamp and C-c ! an inactive one. The prompt takes a date (~2026-12-01~, ~dec 5~, ~12/5~, ~fri~, ~+3d~, ~-1w~, ~+2fri~; a date that has gone by means next year) with an optional time (~14:30~); empty means today. In the Outline view the prompt also shows a month to tap, steppers for the hour and the minutes, and a No time switch. S-up and S-down on a timestamp change the part under the cursor: year, month, day (or weekday), hour, minute, or a repeater's number or unit; on either bracket they switch between active and inactive. S-left and S-right move the date a day. Marking a task with a repeater (~+1w~, ~++1w~, ~.+1w~) DONE moves its date to the next one, on a SCHEDULED or DEADLINE line or on any active timestamp in the entry, and keeps it open.

** Clocking
C-c C-x C-i starts a clock on the heading: a ~CLOCK:~ line in its ~:LOGBOOK:~ drawer. C-c C-x C-o stops it and records the time spent; C-c C-x C-q cancels it. Clocking in on another heading stops the running clock first.

** Effort
C-c C-x e asks for the effort of the heading and sets its ~Effort~ property: ~2:00~, ~2h~, ~30min~ or ~1d~. An empty answer leaves the property empty.

** Agenda files
The agenda covers the files on the agenda files list, not the tabs that happen to be open; a file that is open shows its current text. C-c [ puts the current file on the list and C-c ] takes it off; Settings, Emacs, Agenda files shows the list and adds files from any storage. The list is saved as ~org-agenda-files~, the way an ~init.el~ would set it.

** Agenda
View, then Calendar, shows a month with up to three small squares under each day: green for a birthday, yellow for a holiday, blue for anything else; tap a day to list its entries, and Agenda opens that day in the agenda. Settings, Emacs, Diary file names a file of diary entries (any storage name) and Diary in the agenda shows them with the category Diary, in the calendar too. An entry starts at the left edge with a date (~Nov 5, 2026~, ~11/5/2026~, ~Nov 5~ every year, ~*/15~ the 15th of every month, ~Monday~ every week) or a ~%%(sexp)~ such as ~%%(diary-anniversary 11 20 1990) Anna (%d)~, ~diary-block~, ~diary-float~, ~diary-cyclic~, ~diary-date~, ~diary-remind~ or an expression using ~date~. Date style chooses American, European or ISO dates. A line that starts with a space or a tab continues the entry above it, so a note can run over several lines (the agenda joins them with a semicolon). A date alone on its line with indented events beneath it shows one agenda line for each. A time in the text, such as ~10:00am~ or ~2pm-3:30pm~, becomes the line's time. An ~&~ before a date or a sexp keeps the entry in the agenda but leaves its day unmarked in the calendar. A sexp may run over indented lines in the diary file; in an Org file it is a single line. Birthdays: Settings, Emacs, Contacts files names your contacts files, and a ~%%(org-contacts-anniversaries)~ line in the diary or in an agenda file shows each contact's birthday as ~Birthday: Jane Doe (36th)~. Birthday property changes the property read (BIRTHDAY by default); its value is a date such as ~1990-11-23~, an Org timestamp, or ~11-23~ without a year. Both layouts that org-vcard writes work: the flat one, with ~:BIRTHDAY:~ in the heading's properties, and the tree one, where a child heading with ~:FIELDTYPE: birthday~ holds the date. The calendar also lists holidays: Settings, Emacs, Holidays turns the General, Christian and Solar categories on or off (Solar lists the equinoxes and solstices, and the daylight saving changes, in your time zone), Holidays in the agenda shows them as Diary lines, and Local holidays takes your own as Emacs forms, such as ~(holiday-fixed 3 14 "Pi Day")~, ~(holiday-float 11 4 4 "Fourth Thursday")~ or ~(holiday-sexp '(if (= year 2026) (list 7 4 year)) "Sexp day")~.

View, then Agenda, lists what is scheduled, due or dated in the open files, by Day, Week, 2 weeks, Month or Year; the arrows, a swipe left or right, or f and b move through time, and a tap on a row goes to that heading. Overdue tasks show again on today ("Sched. 3x:" is three days late), deadlines show "In 3 d." as they near, and repeating tasks appear on each of their dates. Views switches to the TODO list, a tags view (a match such as ~work+urgent~) or a search for words. On a day with timed entries a time grid (8:00, 10:00 and so on, with a line for now on today) shows the free hours; Settings, Emacs, Agenda time grid turns it off.

Filter keeps some of the rows: by tag (~+work -home~), category (~+calls~), effort (~<1:00~, ~>0:30~, ~=2:00~; entries with no effort stay only for ~>~) and an Emacs regexp (~+rent~ keeps lines that match, ~-rent~ hides them). The filters show in the title and Clear all filters removes them. Mark turns a tap into a mark; All and None mark every row or none, and Act on N sets the TODO state, adds or removes a tag, sets the priority, schedules, sets a deadline or archives every marked entry. In the Text view C-c a a opens the agenda, C-c a t the TODO list, C-c a m tags and C-c a s a search.

** Capture
C-c c (or Menu, Capture) lists the capture templates by key and description. Tap one, answer its questions, edit the text, and Save files it into the template's target; Cancel drops it.

Emacs's own template, ~t~ Task, which files a TODO under Tasks, is there until you set your own; it files to ~.notes~ in your storage, since Emacs's ~~/.notes~ has no home folder here. A template is set as ~init.el~ writes it, in Settings, Emacs, Capture templates (Reset brings the default back):

#+begin_example
(setq org-capture-templates
  '(("t" "Todo" entry (file+headline "notes.org" "Inbox")
     "* TODO %?\n")))
#+end_example

Types are ~entry~, ~item~, ~checkitem~, ~table-line~ and ~plain~; targets are ~file~, ~file+headline~ (made when missing) and ~file+olp~; options are ~:prepend~, ~:empty-lines~, ~:empty-lines-before~, ~:empty-lines-after~ and ~:immediate-finish~. Escapes: ~%^{Prompt|default}~ or ~%^{Prompt|a|b|c}~ asks, ~%\1~ repeats an answer, ~%<%Y-%m-%d>~, ~%U~, ~%T~, ~%t~, ~%u~, ~%a~ (a link to the heading you were on), ~%i~ (the selected text) and ~%?~ (where the caret starts). With no templates set, Emacs's own Task template files into ~.notes~ under Tasks.

** Refile and archive
C-c C-w lists the places the heading can go; tap one and the heading with its subtree moves there, as its last child. C-c M-w files a copy and keeps the original. In the Outline view, a heading's actions include Refile and Archive.

Which headings are listed is set as ~init.el~ writes it, in Settings, Emacs, Refile targets:

#+begin_example
(setq org-refile-targets '((nil :maxlevel . 2) ("notes.org" :level 1))
      org-refile-use-outline-path t)
#+end_example

A target is a file (~nil~ is this one, ~org-agenda-files~ is the agenda files) with ~:maxlevel~, ~:level~, ~:tag~, ~:todo~ or ~:regexp~. ~org-refile-use-outline-path~ shows the path of each heading, ~org-reverse-note-order~ puts the subtree first instead of last, and ~org-refile-use-cache~ keeps the target list until you run Clear refile cache.

C-c C-x C-a (or C-c $) archives the subtree into the file named in Settings, Emacs, Archive location, ~%s_archive::~ unless you change it; ~::* Archived~ keeps it in the same file under a heading. The entry records when and where it came from in ARCHIVE_TIME, ARCHIVE_FILE, ARCHIVE_OLPATH and ARCHIVE_CATEGORY properties. C-c C-x A moves it under an Archive heading among its siblings, and C-c C-x a toggles the ARCHIVE tag.

** Examples
The ~examples~ folder holds a file for each area: outline, dates, clocking, capture, refile and archive, a weekly review, a project with clocking, find and replace, tables, a diary, contacts with birthdays, and ~config.org~, which lists every setting with an example. The first time the app opens it offers them as sample documents, and File, Sample documents lists them later. One opens as a new tab and is saved only if you save it; follow the line at its top.

** Log settings
Settings, Emacs, Log into drawer names the drawer (such as LOGBOOK) that holds the log line of a repeating task; empty leaves the line in the text. Log repeats is Time, Note or Off: Time adds the log line, Note asks for a note under it too (Skip adds the line alone and the cross leaves it out), Off records nothing when a repeating task is done.

Settings, Emacs, Archive marks done (nil, t or a keyword such as CANCELLED) marks a TODO heading done before it is archived, and Archive saves lists the properties kept on the archived entry (time, file, olpath, category, todo, itags). Refile new headings (Not allowed, Ask first or Allowed) adds New heading under… to the refile list: pick the parent and a title, and the heading is made at the end of the parent's subtree first.

** Settings
Menu, then Settings, sets up GitHub (owner, repository, branch, token) and WebDAV (address, user, password). They are kept in this browser, on this device.

Export writes an Org file of your settings. Give it a passphrase to encrypt the tokens and passwords; without one they are written in plain text, so keep the file private. Import reads such a file on another device and replaces its settings.

If someone changes a file on the server before you save, you can merge the two copies, keep yours, or use theirs.

When you switch to a tab or return to the app, an open file is compared with storage: one without unsaved edits is reloaded, and one with edits says it changed, and saving then asks which copy to keep. Saves made offline are sent when you are back online; the mode line shows how many are waiting. If one clashed with a newer server copy, a list names the files and each is settled the same way.

** Updates
When a new version is ready, the message line says so. Menu, then Restart to update, switches to it; until you do, the version you have keeps running. Settings shows the installed version and, when one is waiting, the new one.

* Run the checks and tests
Needs Node 22 or later and no packages.

: npm run check
: npm test

~npm run check~ verifies licenses, the deny-list, the provenance log and commit sign-offs. ~npm test~ runs every test.
